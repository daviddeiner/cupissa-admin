CUPISSA | Notificaciones push para APP + Administrador

Se modifica únicamente app-cupissa (NO cupissa.com) y el administrador.
Se conserva la lógica previa de pagos, productos, créditos, correos y pedidos.

PASO 1 - Supabase SQL Editor:
Ejecuta el archivo supabase/CONFIGURAR_NOTIFICACIONES_APP.sql.
Utiliza el secreto ya instalado en Vault: cupissa_delivery_service_role.
No coloques ninguna clave privada dentro del administrador ni de la app.

PASO 2 - Supabase Edge Functions:
Crea la función cupissa-push con el contenido de
supabase/functions/cupissa-push/index.ts.
Deja Verify JWT ACTIVADO para permitir solo sesiones válidas y service_role.
Se necesitan las variables de Supabase predeterminadas SUPABASE_URL y
SUPABASE_SERVICE_ROLE_KEY y el secreto CUPISSA_ADMIN_EMAIL (contacto@cupissa.com).
No se modifica cupissa-emails ni cupissa-recordatorio-entrega.

PASO 3 - Publicar:
Actualiza app.cupissa.com con el ZIP app-cupissa actualizado.
Actualiza tu administrador con el ZIP admin actualizado.

PASO 4 - Activar notificaciones en celular:
Abre la aplicación desde Android, inicia sesión, pulsa 'Activar notificaciones'
y concede permiso. Este permiso debe solicitarlo y aceptarlo el cliente;
no se puede activar silenciosamente.

PASO 5 - Probar:
- En Administrador > Notificaciones, escribe título, mensaje y enlace HTTPS.
- Pulsa Enviar. Solo reciben avisos los dispositivos que se suscribieron.
- Cambia el estado de un pedido; se generará aviso para la cuenta vinculada.
- Un cron comprueba la cola cada minuto (puede tardar aproximadamente 1 minuto).
- El aviso de pedido abre la app en el perfil del cliente.

SQL de diagnóstico en SQL Editor:
select id,pedido_id,estado,intentos,error,procesado_en
from public.cupissa_push_outbox order by id desc limit 30;

NOTAS:
- No se envían push a clientes que no concedieron permiso.
- Las notificaciones pueden llegar con la app cerrada si Android admite Web Push.
- Si Play Store usa un contenedor WebView sin Push API, se necesitará
  integración Android nativa (FCM). En Chrome/TWA-PWA puede funcionar Web Push.
- Las claves VAPID se generan al activar el primer teléfono, se guardan en
  una tabla privada con RLS y nunca se entregan completas al navegador.
- El rol service_role y el correo administrativo controlan envíos desde Studio.
